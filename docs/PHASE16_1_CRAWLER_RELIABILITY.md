# Phase 16.1：爬虫成功率、证据确认与数据真实性优化

## 1. 目标

把“搜索到一个网页就尝试抽取”升级为适合电竞馆投资者使用的可靠数据补充流程：

```text
高德 POI
→ 逐条识别真正缺失的字段
→ 规则/AI 生成定向搜索计划
→ 获取多个真实候选网页
→ 规则初筛和 AI 排序
→ 按顺序尝试候选网页
→ 页面相关性校验
→ 字段抽取、边界校验和证据绑定
→ 仅保留有证据的建议值
→ pending_review
→ 人工采用、修改或拒绝
```

成功率提升不能以牺牲真实性为代价。搜索摘要不是业务事实，泛城市页面、百科、旅游攻略和与目标名称/位置不匹配的页面不得写入业务字段。

## 2. 本期实施范围

### 2.1 动态缺失字段

- 竞品按记录判断价格、会员价、机器数、面积、营业时间、上座率是否缺失。
- 配套按记录判断营业时间、夜间营业、24 小时和评分是否缺失。
- 租金按记录判断地址、面积、月租、单价、物业费、转让费、楼层和发布日期是否缺失。
- 搜索计划只围绕缺失字段生成，避免重复抓取已有人工数据。

### 2.2 多候选回退

- 搜索发现返回多个候选 URL。
- 每个候选 URL 独立执行域名、页面相关性、字段充分性检查。
- 第一候选失败时自动尝试下一候选，不立即结束任务。
- 竞品和配套可以从多个已通过目标校验的页面补齐不同字段，排名靠前的来源优先。
- 新租金样本的面积和月租必须来自同一个具体挂牌页，不跨房源拼接。
- 任务结果记录每个 URL 的尝试状态和失败原因。

### 2.3 字段级证据门槛

- 自动写入的每个建议字段必须绑定来源 URL 和原文片段。
- 计算字段（例如月租/面积得到的单价）必须标记 `derived`，并引用其输入字段。
- 没有证据片段的直接抽取字段不写入业务记录。
- 人工字段优先，爬虫只补空值。

### 2.4 人工确认体验

- 竞品、配套、租金统一展示：建议值、来源、证据片段、置信度、待确认提示。
- 用户可以打开来源网页核验。
- 爬虫建议和当前人工值分层展示，不隐藏来源，也不暴露 `raw_data`。
- 确认接口仍使用现有 `confirmed / rejected / pending_review` 状态，不增加新的数据库表。

## 3. 数据真实性规则

1. AI 只能规划搜索词和排序真实候选 URL，不能编造最终 URL。
2. 搜索摘要只参与页面筛选，不能作为字段证据。
3. 页面必须通过名称、位置和业务类型校验。
4. 竞品上座率、营业额、盈利情况不能由通用文本推断。
5. 夜间营业不能由“餐厅”“便利店”等分类自动推断。
6. 租金记录必须同时存在面积和月租，且来自同一挂牌页。
7. `pending_review` 只作为调查线索；正式评分和报告应以 `confirmed` 为事实。

## 4. API兼容

继续复用：

```http
POST /api/projects/{project_id}/crawl/enrich
GET  /api/projects/{project_id}/crawl/tasks
GET  /api/projects/{project_id}/crawl/tasks/{task_id}
```

任务详情增强但不破坏旧字段：

```json
{
  "candidate_attempts": [
    {
      "url": "https://example.com/shop/1",
      "status": "irrelevant",
      "message": "页面未出现目标商户名称"
    },
    {
      "url": "https://example.com/shop/2",
      "status": "accepted",
      "extracted_fields": ["hour_price", "business_hours"]
    }
  ],
  "field_evidence": []
}
```

## 5. 验收标准

- 已有字段不会再次进入主要搜索计划。
- 第一候选无关或抓取失败时会自动尝试第二候选。
- 所有自动建议字段均能追溯到来源和证据片段。
- 租金不会跨两个挂牌页拼接面积和月租。
- 竞品、配套、租金人工确认界面均能看到爬虫建议。
- 不暴露 `raw_data`、调试堆栈或密钥。
- 后端全量测试、前端测试和生产构建通过。

## 6. 后续阶段

- 授权搜索 API 和平台专用 Adapter。
- 来源质量历史评分、字段冲突仲裁和来源过期检测。
- 单字段“采用建议/拒绝建议”审计记录。
- 基于真实开店反馈校准来源可靠性，不将模型推测写入事实库。
