# Phase 16：AI 数据源规划与证据化补充

## 1. 目标

面向电竞馆投资者，把现有“高德 POI → 搜索网页 → 正则抽取”升级为可解释、可追溯的数据补充链路：

```text
高德 POI 候选
→ 判断缺失经营字段
→ 数据源策略目录
→ AI 辅助生成搜索计划（失败时规则兜底）
→ 搜索服务返回真实候选 URL
→ 规则初筛 + AI 对真实 URL 排序
→ 页面目标二次校验
→ 爬虫抓取
→ 结构化抽取和数值边界校验
→ 字段级证据、来源、时间和置信度
→ pending_review
→ 人工确认
→ 数据质量、评分和报告
```

AI 不能凭空生成最终 URL。AI 只能生成搜索词、选择允许的数据源类型，并在搜索服务已经返回的真实 URL 中排序。

## 2. 数据源策略

| 数据对象 | 需要补充的字段 | 优先来源 | 必须人工核实 |
| --- | --- | --- | --- |
| 竞品 | 营业时间、价格、会员价、机器数、硬件配置、面积 | 门店官方页面、公开生活服务页、公开社交内容 | 上座率、营业额、盈利情况 |
| 餐饮与娱乐 | 营业时间、夜间营业、评分 | 官方门店页、高德详情、公开生活服务页 | 夜间真实客流、持续经营状态 |
| 租金 | 面积、月租、单价、物业费、转让费、楼层、发布日期 | 公开房产出租/转让详情页 | 房源真实性、最终成交租金、物业条件 |

登录、验证码、付费墙和明确禁止自动访问的页面不得绕过。页面不可访问时转入人工 URL、文件上传或现场调查。

## 3. 数据真实性

- 高德数据作为基础候选，不等于经营事实。
- 搜索摘要只能用于选择页面，不能直接写入业务字段。
- 页面必须通过名称/地址/业务类型二次校验。
- 每个建议字段保存 `value`、`source_url`、`excerpt`、`collected_at`、`method`、`confidence`。
- 爬虫不得覆盖人工字段。
- 所有爬虫补充默认 `pending_review`。
- 只有 `confirmed` 数据进入正式评分和 AI 报告事实。
- 上座率、营业额、盈利能力等不能由 AI 推测。

## 4. 第一版实施范围

1. 新增电竞馆选址数据源策略目录。
2. 新增 AI 辅助搜索规划；DeepSeek 不可用时自动使用确定性规则。
3. 搜索仍由 Bing/DuckDuckGo 返回真实 URL。
4. AI 排序结果只能引用候选 URL，非法或虚构 URL 自动丢弃。
5. 抽取结果增加字段级证据和抓取置信度。
6. 任务中心显示规划方式、来源域名、建议字段数量和待确认状态。
7. 人工补充页展示竞品爬虫建议值、证据原文和来源链接。
8. 复用 `crawl_tasks` 和现有业务表，不新增数据库表。

## 5. 后续商业化迭代

- 接入授权搜索 API，替代 HTML 搜索页面解析。
- 为已授权的平台开发专用 Adapter，优先读取 JSON-LD 或公开结构化数据。
- 将 AI 抽取限制为 JSON Schema，并增加字段冲突仲裁。
- 建立来源质量评分、过期检测和定期复核。
- 提供投资者版“关键事实、风险、待核实清单”报告视图。
- 通过真实开店反馈校准来源质量和评分规则，但不把模型推测写入长期事实。

## 6. 验收标准

- 高德候选没有 URL 时能生成数据源计划和搜索词。
- DeepSeek 配置可用时记录 `ai_assisted` 计划；失败时不阻断任务。
- AI 返回候选列表之外的 URL 时不会被采用。
- 不相关页面不会写入业务数据。
- 成功抽取字段均带来源、证据、时间和置信度。
- 爬虫建议在人工确认页可见，且不会自动变成 `confirmed`。
- 后端完整测试、前端测试和生产构建通过。
