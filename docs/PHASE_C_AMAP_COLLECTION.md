# Phase C：高德地址解析与 POI 采集闭环

## 目标

Phase C 将高德作为系统唯一自动基础数据来源，形成以下闭环：

```text
项目地址
→ 高德地址解析
→ 多候选地址人工确认
→ 按类别和关键词分页采集
→ 半径过滤与跨关键词去重
→ 写入统一 POI 表
→ 工作台展示采集状态和分类统计
```

本阶段不接入其他地图数据源，不开发爬虫，不估算真实人口，也不修改 AI 报告逻辑。

## 地址解析规则

- 项目已有经纬度时默认直接复用，避免重复解析。
- 地址只返回一个有效候选时自动保存坐标。
- 地址返回多个有效候选时返回 `needs_confirmation`，前端必须让用户选择。
- 地址无结果、超时、网络错误、HTTP 错误和高德业务错误使用不同的业务提示。
- 响应及日志不返回带 Key 的请求 URL。

## POI 采集规则

默认分类：

- `transport`：地铁、公交、停车场。
- `competitor`：网吧、电竞馆、电竞酒店，仅作为疑似竞品线索，后续仍需人工确认。
- `education`：大学、技校、职业院校。
- `residential`：小区、公寓。
- `food`：餐厅、烧烤、夜宵。
- `entertainment`：KTV、酒吧、电影院、台球、密室。

分页和数量限制：

```text
AMAP_POI_PAGE_SIZE=20
AMAP_POI_MAX_PAGES_PER_KEYWORD=3
AMAP_POI_MAX_RECORDS_PER_CATEGORY=100
AMAP_POI_RATE_LIMIT_SECONDS=0.3
```

- 每个关键词按页请求，返回不足一页或达到接口总数时停止。
- 每类记录达到上限时停止该类别，响应标记为 `truncated`。
- 明确排除超出项目分析半径的数据。
- 优先使用高德 POI ID 去重；缺少 ID 时使用名称、地址和六位小数坐标组合去重。

## 返回状态

`POST /api/projects/{project_id}/collect/amap` 返回 `collection_status`：

- `success`：正常获取并保存有效 POI。
- `success_zero`：接口请求成功，但范围内没有有效 POI。
- `partial`：部分关键词成功、部分失败，已保存成功数据。
- `failed`：所有关键词失败或地址解析失败。
- `truncated`：数据有效，但达到配置的页数或类别数量上限。
- `needs_confirmation`：地址存在多个候选，需要先确认坐标。

`diagnostics` 只返回业务诊断，包括：

- 请求关键词数、成功数、失败数。
- 原始返回数、有效数、唯一数、重复数、范围外排除数。
- 每个类别的原始数、唯一数和是否截断。
- 新建数、更新数和采集时间。

## 数据真实性与幂等规则

- 高德未提供的电话、评分、营业时间和经营状态保存为 `null`，不进行推测。
- 高德原始字段及规范化审计字段保存在 `raw_data._amap_fields`。
- 重新采集只更新高德负责的基础字段。
- `manual_detail`、`crawler_detail`、`demo_detail`、审核历史以及 `manual_*` 字段不会被高德覆盖。
- 人工来源 POI 不与高德记录合并，确保来源分层。
- 同一项目重复采集按相同标识更新，不重复新增记录。

## 验证范围

- 多页采集和自动停止。
- 高德 ID 与回退组合键去重。
- 分析半径过滤。
- 类别上限和 `truncated` 状态。
- 多候选地址确认。
- 重复采集不新增重复记录。
- 人工补充内容不被覆盖。
- 前端展示地址候选、采集状态、分类统计、去重数和范围外排除数。

真实 Key 的线上验收应在部署环境执行，不在自动化测试和仓库中保存 Key。
