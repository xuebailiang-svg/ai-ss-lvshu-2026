# Phase H：六步项目流程 UI 收口

## 目标

在不新增业务能力、不改变数据真实性规则的前提下，将项目使用路径收敛为清晰的六步流程，并保证桌面端和窄屏可用。

## 已完成

### 项目列表

- 原横向表格改为紧凑项目卡片。
- 卡片只突出项目名称、地址、当前步骤和业务状态。
- “打开”和“删除”操作固定在卡片底部，不再互相遮挡。
- 删除继续使用二次确认，并保持逻辑删除语义。

### 新建项目

- 增加返回项目列表和取消入口。
- 防止提交过程中重复创建项目。
- 分析范围、预计面积、投资预算的单位与输入框一体显示。
- 三列布局在窄屏自动降为一列。

### 六步工作流

- 删除会在窄屏挤压文字的横向 `Steps`。
- 删除页面顶部重复出现的独立数据采集中心。
- 固定为六张纵向流程卡片：
  1. 输入地址和范围
  2. 获取高德 POI
  3. 查看与人工补充
  4. 数据检查
  5. 确认重要信息
  6. 生成 AI 选址报告
- 顶部只显示当前阶段和下一步建议。
- 已完成步骤使用绿色状态，当前步骤使用蓝色状态，待开始步骤显示前置条件。
- 高德统计、地址候选、采集诊断、人工补充入口、数据检查结论和报告均归入对应步骤。
- 未完成前置步骤时禁用后续关键动作，避免跳步产生无意义结果。

### 人工核实

- 增加疑似竞品、周边配套、租金记录和处理建议概览。
- 保留高德基础字段只读、人工字段单独保存的真实性边界。
- 表格在窄屏内部横向滚动，弹窗宽度不会超过视口。
- 移动端概览卡片自动变为单列，搜索框占满可用宽度。

### 报告展示与导出

- 报告继续作为 Step 6 主内容展示，不混入聊天区。
- 报告标题右侧和报告底部都提供 `导出 HTML`、`打印 / PDF`。
- HTML 导出包含基础排版样式，可脱离系统单独打开和打印。
- 浏览器打印时只打印报告正文，隐藏导航和流程操作。

## 响应式规则

- `> 900px`：页面保持宽屏内容布局，项目卡片按 2 至 3 列展示。
- `<= 900px`：表单、标题区、当前阶段卡片自动改为纵向。
- `<= 600px`：项目卡片单列、操作按钮等宽、流程内容缩小留白，禁止中文被压成逐字竖排。
- 页面只保留浏览器主滚动；只有宽表格自身允许横向滚动。

## 验证

- `npm test -- --run`：11 项通过。
- `npm run build`：成功。
- 构建仍有 Ant Design vendor chunk 超过 500 kB 的警告，不影响本阶段功能；本阶段不做架构性拆包。

## 数据库与后端

- 未新增数据库表、字段或 Alembic migration。
- 未修改高德采集、人工补充、数据准备度、AI 问题和报告真实性规则。
- 未恢复爬虫、评分、Agent、Memory 或政府统计入口。

## 下一阶段边界

Phase H 完成后只进入 Phase I 真实案例验收。真实验收前不继续新增功能；若发现问题，只修复阻塞六步主流程、真实性或部署的缺陷。
