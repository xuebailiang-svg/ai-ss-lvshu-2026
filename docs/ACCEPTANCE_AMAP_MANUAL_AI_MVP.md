## 3. 标准真实案例

### 案例 A：高密度商圈

- 地址：西安市小寨地铁站
- 范围：1000 米
- 业态：电竞馆
- 目标：验证 POI 较多、疑似竞品较多时的去重、分类、人工核实和报告性能。

### 案例 B：社区商圈

- 地址：陕西省西安市雁塔区西部电子社区
- 范围：500 米
- 业态：电竞馆
- 目标：验证社区型商圈中交通、住宅、餐饮、娱乐和疑似竞品的真实返回。

### 边界案例

1. 同名或歧义地址：必须出现候选地址确认，不能擅自选错坐标。
2. POI 稀疏地址：允许真实零结果，必须显示“数据不足”，禁止生成虚构商户。
3. 不填写租金/竞品详情：AI 只能有限提问，报告必须明确未知。
4. 补齐候选物业和核心竞品后重新生成：旧报告快照不被覆盖，新报告使用新快照。

## 4. 六步人工验收

### Step 1 输入地址和范围

- [ ] 项目名称、城市、区域、详细地址、范围、面积、预算单位明确。
- [ ] 创建按钮提交期间不可重复点击。
- [ ] 地址定位成功后显示正确城市、区县、经纬度。
- [ ] 地址有歧义时必须人工选择候选项。
- [ ] 返回项目列表后项目卡片可重新打开，删除操作有二次确认。

证据：项目截图、地址候选截图、项目 ID（不得粘贴 Key）。

### Step 2 获取高德 POI

- [ ] 高德连接测试成功。
- [ ] 页面展示 `collection_status` 对应的成功、部分成功、截断、零结果或失败说明。
- [ ] 页面显示 POI、交通、疑似竞品、教育、住宅、餐饮、娱乐分类数量。
- [ ] 展示原始返回数、去重数、范围外排除数和达到上限的分类。
- [ ] 同一项目重复采集不产生重复 POI。
- [ ] `project.stats.poi_count` 与 `/dataset` 中 `pois` 数量一致。

证据：采集结果截图、`acceptance-mvp.sh --project-id` 输出、失败关键词（如有）。

### Step 3 查看与人工补充

- [ ] 疑似竞品名称、地址、距离来自高德并保持只读。
- [ ] 可将候选标记为真实竞品或排除。
- [ ] 可补充机器数、硬件、价格、营业时间和现场上座率；未知字段可明确标记。
- [ ] 配套可确认/排除，营业时间等人工字段不会被高德重采集覆盖。
- [ ] 候选物业地址、面积、月租、用途、供电、消防、网络和入口条件可保存。
- [ ] 刷新页面后人工数据仍存在，修改时间和来源可追溯。

证据：补充前后截图、刷新后截图、人工核实时间。

### Step 4 数据检查

- [ ] 固定显示技术前置、关键未知、建议补充、可选信息四组。
- [ ] 准备度只描述数据齐备程度，不描述成功概率或盈利概率。
- [ ] 缺少租金、消防、物业用途等信息时明确列出。
- [ ] 被排除的数据不进入有效统计。

证据：数据检查截图和缺失项记录。

### Step 5 确认重要信息

- [ ] AI 每轮最多询问规定数量的问题，不无限追问。
- [ ] 问题只来自固定字段目录和当前缺失项。
- [ ] 用户回答、明确未知、跳过三种状态可以区分。
- [ ] AI 不要求用户提供不可合理获得的营业额、盈利或真实客流。
- [ ] 保存后重新检查，相关缺失项状态正确变化。

证据：问题列表、答案保存反馈、保存后的数据检查截图。

### Step 6 生成 AI 选址报告

- [ ] DeepSeek 连接测试成功；未配置时给出明确提示。
- [ ] 报告包含固定八个章节，目录与正文层级清楚。
- [ ] 报告明确区分高德事实、人工提供、确定性计算和未知。
- [ ] 抽查所有关键数字，均能在最终项目快照或确定性计算中找到。
- [ ] 不出现推测营业额、上座率、利润、真实人口或真实客流。
- [ ] 信息不足时生成“数据不足”结论，不用模拟数据填满报告。
- [ ] 标题处和报告底部均能导出 HTML、打印/PDF。
- [ ] HTML 单独打开排版正常；PDF 无按钮、导航、截断和中文竖排。

证据：报告快照版本、数字核对表、HTML 文件、PDF 文件和截图。

## 6. 数据来源核对表

| 数据类型 | 允许来源 | 是否可直接作为事实 | 必须显示的边界 |
|---|---|---|---|
| 项目地址/范围/预算 | 用户输入 | 是 | 用户提供 |
| POI 名称/地址/距离/高德营业时间 | 高德 Web Service | 是 | 高德返回、采集时间、分析半径 |
| 竞品是否真实有效 | 人工确认 | 是 | 核实时间和方式 |
| 竞品价格/硬件/现场上座率 | 人工调查 | 是 | 来源、观察时间；缺失即未知 |
| 候选物业租金/消防/供电/用途 | 用户或现场调查 | 是 | 当前物业，不等于周边均价 |
| 数据准备度 | 固定规则计算 | 是 | 不是成功率、盈利概率或评分 |
| AI 文本 | DeepSeek 基于最终快照 | 只可解释已确认事实 | 不能创造新数字或事实 |
| 爬虫、政府统计、Memory、Agent、评分 | 收敛版 MVP 排除 | 否 | 不进入最终快照和报告 |

## 8. 缺陷分级与发布门槛

| 等级 | 定义 | 示例 | 发布处理 |
|---|---|---|---|
| P0 | 数据安全或真实性事故 | Key 泄露、报告编造数字、人工字段被覆盖 | 必须修复，禁止发布 |
| P1 | 主流程不可完成 | 无法创建/采集/补充/检查/生成报告 | 必须修复或明确阻断方案 |
| P2 | 体验明显受损 | 移动端按钮遮挡、导出排版异常 | 记录并安排最近修复 |
| P3 | 文案或轻微视觉问题 | 间距、提示语不一致 | 可后续修复 |

每个问题记录：环境、项目 ID、步骤、预期、实际、截图、关键英文错误原文、严重级别、修复 commit、复测结果。
