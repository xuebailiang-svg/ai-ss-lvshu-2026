# Phase 16.2—16.7 实施说明

## 目标

把“搜索网页并直接填字段”的实验能力升级为面向电竞馆投资人的可审核数据生产线：任务可重试、字段有证据、来源有质量等级、冲突不静默覆盖、报告可追溯、真实经营结果可沉淀为经验。

## Phase 16.2：任务可靠性

- 失败或跳过任务支持一键重试，重试会复制原始输入并建立新任务，不覆盖历史任务。
- 任务列表继续展示搜索、抓取、相关性、抽取和保存状态；保留每个候选页的尝试结果。
- Worker 仍使用独立进程和独立数据库 Session，HTTP 请求只负责创建任务。

## Phase 16.3：字段级证据审核

- 新增 `crawler_field_suggestions`，每个候选字段独立保存值、来源 URL、证据摘录、置信度和审核状态。
- 审核支持接受、修改后接受、拒绝；接受后只写入对应项目和记录。
- 接受字段不会自动把整条商户或租金记录标记为 `confirmed`，整条记录仍需人工确认。

## Phase 16.4：Provider 与 Adapter

- 搜索发现通过 `SearchProvider` 注册表调用，便于增加合规搜索 API。
- 页面抽取通过 `WebsiteAdapter` 注册表选择；优先读取 JSON-LD，失败后回退通用规则。
- 不提供登录、验证码、付费墙或反爬绕过。

## Phase 16.5：来源质量、时效和冲突

- 字段证据增加 `source_quality`、`freshness_status`。
- 多页面对同一字段给出不同值时标记冲突，保留第一条证据，不自动覆盖。
- 搜索结果页、百科和内容聚合页默认低质量；官方或结构化详情页可获得更高等级。

## Phase 16.6：报告证据附录

- AI 输入增加已确认爬虫证据摘要，不发送待审核建议作为事实。
- 报告固定增加“数据证据与可信度附录”，列出字段、来源域名、证据和审核状态。
- 报告仍禁止推测营业额、上座率、盈利和真实客流。

## Phase 16.7：经营反馈闭环

- 新增 `business_outcomes`，记录实际租金、面积、机器数、开业日期、投资额、上座率和成败原因。
- 反馈默认待审核；确认后生成或更新 `case_feedback` 项目记忆，供后续案例参考。
- AI 推测内容、待审核反馈和被拒绝反馈不会进入长期记忆。

## 数据真实性边界

```text
搜索结果 → 抓取 → 字段证据 → pending_review
                              ↓ 人工逐字段审核
                         accepted / rejected
                              ↓ 整条记录确认
                    评分与 AI 报告正式事实
```

任何自动结果均不能跳过人工确认，冲突字段不得静默覆盖，来源链接必须保留。
