## 2. 检查结论

### 2.1 功能可用性

代码级流程完整，支持项目创建、基础数据采集、公开网页线索补充、人工确认、数据核验、评分、AI 报告和导出。

本轮发现的主要流程问题是：数据核验、评分和报告按钮此前允许用户跳步，容易在数据为空时生成低价值结果。现已增加前置条件：

1. 项目存在有效采集数据后，才可执行数据核验。
2. 数据核验完成后，才可执行评分。
3. 评分完成后，才可生成 AI 报告。

### 2.2 流程顺畅度

工作台已有 8 步卡片，但用户仍缺少全局完成感知。本轮已增加：

- 流程完成进度条。
- “已完成 X/8 步”提示。
- 当前步骤和下一步保持醒目。
- 未满足前置条件的按钮直接禁用，防止误操作。

### 2.3 界面与报告

现有报告已经具备封面、摘要、目录、Markdown 正文、来源说明、HTML 导出和打印/PDF。主要问题是报告生成后，用户不容易快速判断其数据是否可用于决策。

本轮已增加：

- 报告“数据可信状态”：数据较完整、数据待补充、存在待确认线索、仅限演示。
- 数据完整度不足、存在爬虫待确认线索或使用演示数据时，在正文上方显示醒目阅读提示。
- 报告摘要改为自适应栅格，窄屏不再挤压。
- 城市洞察图表按需加载，减少不需要图表时的资源开销。
- 修复 AI 偶尔把 Markdown 表格压成一行时，页面直接显示竖线文本的问题。
- 全流程完成后显示“流程已完成”，不再错误回到 Step 1。
- 项目列表将“数据较完整”改为“基础数据已采集”，避免把采集数量误认为质量合格。
- 已有独立爬虫 Provider 时隐藏旧的通用“爬虫数据尚未开发”占位项，避免状态冲突。

### 2.4 数据完整性

系统可以组合以下数据：

- 高德 POI：名称、地址、坐标、距离和分类等基础事实。
- 政府公开数据：城市或区县宏观人口、经济、消费、就业背景。
- 爬虫：公开网页中的待核实线索。
- 人工补充：竞品经营、配套营业、真实租金和物业条件。

但“数据获取完整”不能等同于“所有真实经营数据均可自动获取”。以下数据仍必须人工核实或通过授权数据源接入：

- 竞品实际价格、机器配置、真实上座率、营业额。
- 真实商铺租金、物业费、转让费及可租状态。
- 商户夜间营业状态。
- 1km 真实居住人口、工作人口、小时客流和客群画像。
- 物业电力、消防、租赁条款和整改成本。

爬虫数据必须保持 `pending_review`，不得覆盖人工字段，不得未经确认进入正式评分事实。

## 6. 下次部署后回归清单

按以下顺序执行一次真实项目：

1. 打开工作台和配置页，确认无白屏、错位和 Console error。
2. 新建“小寨地铁站、1000 米、电竞馆”项目。
3. 获取高德 POI，核对数量及地图范围。
4. 获取城市公开数据，核对来源、年份和行政区口径。
5. 执行爬虫任务，确认结果只作为待审核线索。
6. 在人工补充页确认至少 3 个竞品、3 个配套和 3 条有效租金。
7. 执行数据核验，检查已有项、缺失项和补充入口。
8. 完成评分，确认各维度分数与数据来源一致。
9. 生成 AI 报告，检查交通、竞品、夜间消费、租金、城市背景、风险和数据缺口章节。
10. 导出 HTML，并使用浏览器打印为 PDF，检查分页、表格和中文显示。
